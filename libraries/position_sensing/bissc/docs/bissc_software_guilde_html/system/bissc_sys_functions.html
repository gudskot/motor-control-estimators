5. System-Level Functions

This section describes functions which act at the system-level. This includes initialization of the C2000 device, start-up functions and interrupt service routine.

Many of these functions make calls to the BiSS-C Library which is described in API Library Documentation.

5.1. System Initialization Functions

Most of the initialization function calls to driverlib or to functions generated by the system .syscfg file. The bissc_init() function leverages these plus performs some additional BiSS specific initializations.

void bissc_init(PM_bissc_scdStruct_Handle, PM_bissc_cdStruct_Handle)

Initialize the BiSS-C Interface.

This example function initializes variables, the CLB and other peripherals required to integrate the BiSS-C encoder interface communications library into a C28x application.

This includes:

  • Configure the device GPIO, XBAR, SPI. This code is generated by the demo project’s syscfg file

  • Load the CLB tile configuration from the library

  • Configure the CLB to generate the required duty cycle for the BiSS-C MA signal (clock)

  • Initialize SCD and CD parameters used by the library

  • Configure the SPI interrupt

  • Enable power to the encoder

Returns

None.

5.2. System Run-time Functions

The following system-level functions are called during run-time.

void bissc_runSystem(PM_bissc_scdStruct_Handle, PM_bissc_cdStruct_Handle, PM_bissc_registerStruct_Handle, PM_bissc_encoderStruct_Handle, bissc_diagnosticsStruct_Handle) __attribute__((ramfunc)) __attribute__((noreturn))

Run the communication demonstration.

This example function demonstrates how to call into the BiSS-C library to perform single-cycle-data transactions and read/write from registers.

This function runs an infinite while() loop:

  1. Execute the command data state-machine and check for pass/fail status

  2. Initiate single-cycle data transactions

  3. Wait for the SCD response be received and read in the SPI RX ISR routine

  4. Call the library’s parser function to extract the position, CRC and CDS bit from the received SCD stream

  5. Check the parser’s return value for pass or fail status

Returns

None.

void bissc_setupCDTest(PM_bissc_cdStruct_Handle cdParams, PM_bissc_registerStruct_Handle registerParams) __attribute__((ramfunc))

Test control data, CD, register read and write.

This function configures a CDM stream for register accesses.

The BISSC_BANK_SELECT register (address 0x40) is used for both read and write accesses. This register is typically safe to write to without causing any undesired issues.

The test routine consists of 6 tests numbered 0-5.

Test 0, 2, and 4:

  • Setup a CDM stream to read the BISSC_BANK_SELECT register

Test 1, 3, and 5:

  • Log the previous read in the bisscRegisterReadData array

  • Setup a CDM stream to write to the BISSC_BANK_SELECT register.

Note

As provided:

  • The bisscRegisterReadData[] is a circular buffer of size BISSC_READ_COUNT. Old values will be overwritten.

  • The value written to the register corresponds to the test number (1, 3, or 5)

  • This test assumes the value written is a valid bank for the connected encoder.

  • The first read will depend on the value in the register at startup. The subsequent reads should alternate between the written values (1, 3, 5, 1, 3, 5…)

Parameters

  • cdParams – Control data frame parameters

  • registerParams – Register address, access type and data

Returns

None

void bissc_spiRxISR(void) __attribute__((interrupt("HPI"))) __attribute__((ramfunc))

Service the SPI FIFO receive interrupt.

This interrupt service routine copies the contents of the SPI RX FIFO into the scdRxData array

Note

This interrupt service routine is defined as a high-priority interrupt for performance reasons. This means the ISR can not be interrupted by another ISR (no nesting allowed). Refer to the C2000 compiler guide for more information.
