************************************************************
Migrating from an Earlier Version
************************************************************

.. _lnk-migration:

The C2000 Motor Control SDK V4.01.00_00 release implemented important changes.  
These changes improve performance, increase ease-of-use, and utilize new device features.

The changes fall into two categories:

* Code Changes: Changes that require you to modify your source code.
* Design Changes: Changes that may not impact your code.  These primarily use new device features, but are not required.

A specific list of changes are described in the following sections.

Code Changes
-----------------------------

The suggested steps to migrate an application to the new library are:

Review the system example
++++++++++++++++++++++++++++++++++++++++++++++++++++

Illustrates the MCU setup and invokes each of the T-format commands.

Global variable changes
++++++++++++++++++++++++++++++++++++++++++++++++++++

Refer to :ref:`global variables <lnk-lib-globals>`.  The tformatData structure has changed slightly:
  
#. The tformatRxData[] array is now separate from the tformatData structure. tformatRxData and must be defined in your application.
#. tformatData variable names were updated for clarity.
#. Position and Turns were removed and added to an application level structure.

In the application demo, the following variables have been added to collect data.  They are not required by the library.

#. errorData: detected errors are flagged
#. encoderData: encoder position, turns, and id
#. commandData: Command information (command field sent, address, data) can be used by the application for error checking against the command information received.
#. tformatSpiRxIsrTicker: Increments once each time the SPI receive interrupt service routine is called.

SPI ISR changes in tformat_spiRxISR
++++++++++++++++++++++++++++++++++++++++++++++++++++ 

#. Update the ISR to mask the data (with 0xFF) as it is read from the FIFO.
#. Update the ISR to use tformatRxData[]
#. The use of MUST_ITERATE was added to improve performance. Refer to |COMPILER_GUIDE|_.
#. Refer to the system demonstration code for an example.

Command (request) setup changes
++++++++++++++++++++++++++++++++++++++++++++++++++++

* PM_tformat_setupCommand() split into 3 functions based on the fields transmitted. 
* Refer to :ref:`deprecated command functions <lnk-lib-deprecated>`.
  
Receive data changes
++++++++++++++++++++++++++++++++++++++++++++++++++++

* PM_tformat_receiveData() split into 5 functions based on the fields received. 
* Refer to :ref:`deprecated command functions <lnk-lib-deprecated>`.
  
CRC calculations moved to the library
++++++++++++++++++++++++++++++++++++++++++++++++++++

* Application level CRC calls are no longer required and can be removed.
* The calculations are included in the setup command and the received data functions. 
* The CRC result is passed to the application through the tformatData.crcCheck variable.  
* The application can compare tformatData.crcCheck to tformatData.crcField (CRC received from the encoder).  
  
New API functions
++++++++++++++++++++++++++++++++++++++++++++++++++++

* PM_tformat_updatePositionOrTurns() and PM_tformat_updateEncoderID()
* New functions added. Previously the translation from response received was left to the application. 
* Refer to :ref:`Update encoder parameters <lnk-lib-encoder_parameters>`.

Design Changes
-----------------------------

These design changes are included in the library or system examples.  There is no specific action to take. They are listed here for reference.

Receive CRC generation (requires CLB type 2)
++++++++++++++++++++++++++++++++++++++++++++++++++++

Devices with Type2 CLB, or later, can calculate the RX CRC as the response from the encoder is received.  The library uses this option when available. Refer to :ref:`system and library configuration instructions <lnk-configuration>`. No application level change is required.

Transmit CRC generation (requires VCRC module)
++++++++++++++++++++++++++++++++++++++++++++++++++++

When available, the library uses the VCRC module to generate the TX CRC. TX CRC is used by the EEPROM write and EEPROM read commands. Refer to :ref:`system and library configuration instructions <lnk-configuration>`. No application level change is required.

CLB_SPI_CLK (out) to SPICLK (in) pin connection (requires CLB type 2)
++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++

Internal clocking of the SPICLK pin. Devices with CLB type 2, or later, are capable of connecting to the SPICLK (in) directly. Externally connecting the CLB_SPI_CLK output to the SPICLK pin input is not required.  The CLB design takes advantage of this feature when available.  In such a case, the SPICLK can optionally be brought out to a pin to be monitored. Refer to the input/output details in the |TFORMAT_LIB_NAME|_.

SPICLOCK alignment with data
++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++

Previously the CLB_SPI_CLK was only aligned with the first falling edge of the encoder's response.  LUT0 has been modified to re-align the clock when any edge (falling or rising) within the response is received.

FIFO wordsize
++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++

The FIFO word size has been aligned with the T-format field size.  Previously the word size was set to 16-bits.  This change simplified extracting the fields from the FIFO. 

INPUTXBAR and OUTPUTXBAR usage
++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++

CLB_INPUTXBAR and CLB_OUTPUTXBAR were used in favor of device-level INPUTXBAR/OUTPUTXBAR on devices supporting this feature.
