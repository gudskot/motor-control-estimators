3. Migrating from an Earlier Version¶

The C2000 Motor Control SDK V4.01.00_00 release implemented important changes. These changes improve performance, increase ease-of-use, and utilize new device features.

The changes fall into two categories:

  • Code Changes: Changes that require you to modify your source code.

  • Design Changes: Changes that may not impact your code. These primarily use new device features, but are not required.

A specific list of changes are described in the following sections.

3.1. Code Changes¶

The suggested steps to migrate an application to the new library are:

3.1.1. Review the system example¶

Illustrates the MCU setup and invokes each of the T-format commands.

3.1.2. Global variable changes¶

Refer to global variables. The tformatData structure has changed slightly:

  1. The tformatRxData[] array is now separate from the tformatData structure. tformatRxData and must be defined in your application.

  2. tformatData variable names were updated for clarity.

  3. Position and Turns were removed and added to an application level structure.

Listing 3.1 /boostxl_posmgr/f28003x/source/pm_tformat_main.c¶
    //
    // Globals used by the library
    // - Lookup table for CRC calculations
    // - tformatData structure to track key parameters.
    //
    PM_tformat_DataStruct tformatData;
    volatile uint16_t tformatRxData[PM_TFORMAT_FIELDS_MAX];

    #if defined(PM_TFORMAT_CRC_TABLE)
        uint16_t tformatCRCtable[PM_TFORMAT_CRCTABLE_SIZE];
    #endif

    //

In the application demo, the following variables have been added to collect data. They are not required by the library.

  1. errorData: detected errors are flagged

  2. encoderData: encoder position, turns, and id

  3. commandData: Command information (command field sent, address, data) can be used by the application for error checking against the command information received.

  4. tformatSpiRxIsrTicker: Increments once each time the SPI receive interrupt service routine is called.

Listing 3.2 /boostxl_posmgr/f28003x/source/pm_tformat_main.c¶
    //
    // These structures are used to display the received
    // data in Code Composer Studio's Expressions
    // window during development.  Because the structure is
    // set, but never used, the pragma RETAIN
    // has been applied.  Volatile is used for the
    // tformatSpiRxIsrTicker since it is updated within
    // the SPI ISR.
    //
    #pragma RETAIN (encoderData);
    #pragma RETAIN (errorData);
    #pragma RETAIN (commandData);

    PM_tformat_encoderStruct encoderData;
    PM_tformat_errorStruct errorData;
    PM_tformat_commandStruct commandData;
    volatile uint32_t tformatSpiRxIsrTicker;

    //

3.1.3. SPI ISR changes in tformat_spiRxISR¶

  1. Update the ISR to mask the data (with 0xFF) as it is read from the FIFO.

  2. Update the ISR to use tformatRxData[]

  3. The use of MUST_ITERATE was added to improve performance. Refer to TMS320C28x Optimizing C/C++ Compiler User’s Guide.

  4. Refer to the system demonstration code for an example.

Listing 3.3 /boostxl_posmgr/shared/source/tformat.c¶
//
    #pragma MUST_ITERATE(5, 12, 1)
    for (i = 0; i < tformatData.fifoLevel; i++)
    {
        tformatRxData[i] = SPI_readDataNonBlocking(PM_TFORMAT_SPI) & 0xFF;
    }

//

3.1.4. Command (request) setup changes¶

  • PM_tformat_setupCommand() split into 3 functions based on the fields transmitted.

  • Refer to deprecated command functions.

3.1.5. Receive data changes¶

  • PM_tformat_receiveData() split into 5 functions based on the fields received.

  • Refer to deprecated command functions.

3.1.6. CRC calculations moved to the library¶

  • Application level CRC calls are no longer required and can be removed.

  • The calculations are included in the setup command and the received data functions.

  • The CRC result is passed to the application through the tformatData.crcCheck variable.

  • The application can compare tformatData.crcCheck to tformatData.crcField (CRC received from the encoder).

3.1.7. New API functions¶

  • PM_tformat_updatePositionOrTurns() and PM_tformat_updateEncoderID()

  • New functions added. Previously the translation from response received was left to the application.

  • Refer to Update encoder parameters.

3.2. Design Changes¶

These design changes are included in the library or system examples. There is no specific action to take. They are listed here for reference.

3.2.1. Receive CRC generation (requires CLB type 2)¶

Devices with Type2 CLB, or later, can calculate the RX CRC as the response from the encoder is received. The library uses this option when available. Refer to system and library configuration instructions. No application level change is required.

3.2.2. Transmit CRC generation (requires VCRC module)¶

When available, the library uses the VCRC module to generate the TX CRC. TX CRC is used by the EEPROM write and EEPROM read commands. Refer to system and library configuration instructions. No application level change is required.

3.2.3. CLB_SPI_CLK (out) to SPICLK (in) pin connection (requires CLB type 2)¶

Internal clocking of the SPICLK pin. Devices with CLB type 2, or later, are capable of connecting to the SPICLK (in) directly. Externally connecting the CLB_SPI_CLK output to the SPICLK pin input is not required. The CLB design takes advantage of this feature when available. In such a case, the SPICLK can optionally be brought out to a pin to be monitored. Refer to the input/output details in the C2000 T-Format Encoder Interface TI Design (TIDM-1011).

3.2.4. SPICLOCK alignment with data¶

Previously the CLB_SPI_CLK was only aligned with the first falling edge of the encoder’s response. LUT0 has been modified to re-align the clock when any edge (falling or rising) within the response is received.

3.2.5. FIFO wordsize¶

The FIFO word size has been aligned with the T-format field size. Previously the word size was set to 16-bits. This change simplified extracting the fields from the FIFO.

3.2.6. INPUTXBAR and OUTPUTXBAR usage¶

CLB_INPUTXBAR and CLB_OUTPUTXBAR were used in favor of device-level INPUTXBAR/OUTPUTXBAR on devices supporting this feature.
