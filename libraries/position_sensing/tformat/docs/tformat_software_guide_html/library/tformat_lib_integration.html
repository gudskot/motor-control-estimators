1. T-Format Library Integration¶

Reference the included System Example as a blueprint for integrating the library into an application. This section provides an overview of the steps required.

1.1. Resolve Resource Conflicts¶

Review the resources used by the T-Format Encoder Interface. The resource utilization is described in TIDM-1011.

Resolve any resource conflicts with your specific application. Include the CLB tiles, XBARS and GPIO pins in this evaluation. In some cases, a specific resource was used due to the LaunchPad pinout. Your own application may have different hardware requirements and limitations. For example, a specific CLB tile may be able to access a GPIO through a specific XBAR.

1.2. Add Header Files¶

Include the following header files in the project source:

  1. T-Format library header file: #include "pm_tformat_include.h"

  2. System functions header file: #include "tformat.h"

1.3. Update Code Composer Studio Search Locations¶

CCS searches specific locations for header files and the library (.lib) files. Referring to the directory structure and update the search locations by the following steps:

  1. In Code Composer Studio Project Explorer window: Right click project name

  2. Select: Properties -> Build -> C2000 Compiler Options -> Include Options

  3. Add the directory path for each include file to the compiler search path.

  4. Once again, Right click project name

  5. Select: Properties -> Build -> C2000 Linker -> File search Path.

  6. Include the library binary in the linker options. For example: pm_tformat_f28003x.lib

  7. Add the directory path for the lib to the library search path.

1.4. Add System-Level Functions¶

The System Example includes functions which you may wish to include in your project. Depending on your specific needs, you can copy functions or include the source files from the example by following these steps:

  1. In Code Composer Studio: Right click project name

  2. Select: Add Files

  3. Select the file(s) to include.

1.5. Create Global Structures¶

The library requires global variables to share data between modules and with the system.

Listing 1.3 /boostxl_posmgr/f28003x/source/pm_tformat_main.c¶
    //
    // Globals used by the library
    // - Lookup table for CRC calculations
    // - tformatData structure to track key parameters.
    //
    PM_tformat_DataStruct tformatData;
    volatile uint16_t tformatRxData[PM_TFORMAT_FIELDS_MAX];

    #if defined(PM_TFORMAT_CRC_TABLE)
        uint16_t tformatCRCtable[PM_TFORMAT_CRCTABLE_SIZE];
    #endif

    //

There are additional globals that are used by this specific system example. These are not required for BiSS-C communication, but may be useful in your application. These are shown below.

    //
    // These structures are used to display the received
    // data in Code Composer Studio's Expressions
    // window during development.  Because the structure is
    // set, but never used, the pragma RETAIN
    // has been applied.  Volatile is used for the

1.6. Initialize the System¶

Refer to the example system initialization functions. Some functions may require modification for your specific system. Check that the TFORMAT_FREQ_DIVIDER is correctly defined for your device CLB clock frequency. This is defined in the system tformat.h header file.

1.7. Implement Background Loop, SPI ISR¶

Use the provided system run-time functions as a template, implement the following functions:

End-of-frame interrupt (SPI RX ISR)

Populate the RX data array with the content of the SPI RX FIFO.

Listing 1.5 /boostxl_posmgr/shared/source/tformat.c¶
//
    #pragma MUST_ITERATE(5, 12, 1)
    for (i = 0; i < tformatData.fifoLevel; i++)
    {
        tformatRxData[i] = SPI_readDataNonBlocking(PM_TFORMAT_SPI) & 0xFF;
    }

//

Send Commands and Receive Response

An example of the run-time flow is shown below:

Listing 1.6 /solutions/boostxl_posmgr/shared/source/tformat.c¶
        //
        // 1) Setup the command
        // 2) Start the operation (transmission)
        // 3) Wait for the response to be received by the SPI.
        //    The SPI RX FIFO ISR will set the dataReady flag.
        // 4) Unpack, or receive, the data.
        // 5) System specific: check and respond to errors
        // 6) Update any encoder parameters (position, turns, ID)
        //
        PM_tformat_setupCommandReadoutOrReset(PM_TFORMAT_ID0,
                                PM_TFORMAT_RX_CLOCKS_ID0,
                                PM_TFORMAT_RX_FIELDS_ID0,
                                PM_TFORMAT_TX_CLOCKS_ID0,
                                PM_TFORMAT_FIFO_LEVEL_ID0);
        PM_tformat_startOperation();
        while(tformatData.dataReady != true) {}
        PM_tformat_receiveDataID0_1_7_8_C();
        if(tformat_checkError(PM_TFORMAT_CFID0) != PM_TFORMAT_PASS)
        {
            ESTOP0;
        }
        encoderData.position =
                PM_tformat_updatePositionOrTurns(tformatData.dataField0,
                                                 tformatData.dataField1,
                                                 tformatData.dataField2);
        //
