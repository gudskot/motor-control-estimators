5. Library Private Functions¶

The following functions are not called directly by the application. They are called from other functions within the library.

5.1. Initialization Functions¶

void tformat_initCLBXBAR(void)¶

Configure the CLB XBAR.

Configures the CLB XBAR. This function is generated by SysConfig

Returns

None.

5.2. Run-time Configuration Functions¶

static inline void tformat_configureCLBLen(uint16_t transmitClocks, uint16_t receiveClocks) __attribute__((ramfunc))¶

Configure the CLB.

Configures the CLB as required for the specific command.

Returns

None.

static inline void tformat_configureSPILen(void) __attribute__((ramfunc))¶

Configure the SPI FIFO depth.

Configures the PM_TFORMAT_SPI FIFO depth as required for the specific command.

Uses the global parameter tformatData.fifoLevel to set both the TX and the RX SPI FIFO level.

Returns

None.

static inline void tformat_resetCLB(uint16_t tformatRXFields) __attribute__((ramfunc))¶

Reset the CLB.

Reset portions of the CLB. Configure the CLB for the next transaction with the encoder

Parameters

  • tformatRXFields – The number of fields in the expected response this is in the form PM_TFORMAT_RX_FIELDS_IDx where x is the ID number of the command

Returns

None.

5.3. CRC Run-time Functions¶

Which CRC generation method is used depends on the library configuration.

Refer to the configuration section for more information.

Listing 5.1 /libraries/position_sensing/tformat/include/pm_tformat_include.h¶
//
// Define how the CRC is generated. Supported options are:
//
// #define PM_TFORMAT_RX_CRC_BY_C28X
// #define PM_TFORMAT_TX_CRC_BY_C28X
//     The CRC for the data (TX or RX) is generated by the C28x using a
//     lookup table. This method takes the most C28x bandwidth and
//     memory.
//
// #define PM_TFORMAT_RX_CRC_BY_CLB
//     The received data CRC is generated on-the-fly by the CLB as the
//     data is received.
//     This requires 1 CLB tile.
//     This option requires CLB type 2 or later.
//
// #define PM_TFORMAT_TX_CRC_BY_VCRC
//     The transmit data CRC is generated by the VCRC extension to the C28x.
//     This option requires that the device has the VCRC extension.
//
uint16_t tformat_getCRCID0_1_7_8_C(void) __attribute__((ramfunc))¶

Calculate the return data CRC for a specific command ID.

This function creates a data packet from the tformatData structure. The data fields used are specific to the command ID identified in the name of the function. For example tformat_getCRCID2() will use response data fields specific to command ID2.

Depending on the device, different features may be used to generate actual the CRC value. This function calls the appropriate CRC routine based on the library’s configuration.

See

The getCRCIDx functions are:

  • tformat_getCRCID0_1_7_8_C Valid for ID0, ID1, ID7, ID8 and IDC

  • tformat_getCRCID2 Valid for ID2

  • tformat_getCRCID3 Valid for ID3

  • tformat_getCRCIDD Valid for IDD

  • tformat_getCRCID6 Valid for ID6

Returns

crcResult 8-bit calculated CRC value

5.3.1. CLB CRC¶

uint16_t tformat_getRxCRCbyCLB() __attribute__((ramfunc))¶

Get the CRC for a received response.

Get the CRC of the encoder’s response. The CRC calculation is performed while the response is received.

To use this function, set 

#define PM_TFORMAT_RX_CRC_BY_CLB 1
in the library header file.

Note

Requires CLB type 2 or later and one CLB tile. It is assumed the CLB tile has been properly configured during system initialization.

Returns

CRC 8-bit calculated CRC

5.3.2. VCRC CRC¶

uint16_t tformat_getTxCRCbyVCRC(uint16_t *msgBuffer)¶

Calculate T-Format transmit data CRC using the VCRC.

Calculate the CRC for a T-format transmit operation. The polynomial, polynomial size and data size are hard-coded for the T-format protocol.

Note

The C28x VCRC extension calculates the CRC. VCRC is not available on all devices. Refer to the device-specific data sheet.

Warning

This function assumes it will not interrupt another VCRC calculation. That is, this function does not context save the VCRC, VCRCPOLY and VCRCSIZE registers upon entry. If this not the case, the user must add the context save and restore.

Parameters

  • msgBuffer – Pointer to the message buffer

Returns

crcResult 8-bit calculated CRC value

5.3.3. C28x Look-up Table CRC¶

uint16_t tformat_getCRC(uint16_t nBitsData, uint16_t *msg, uint16_t *crcTable, uint16_t rxLen) __attribute__((ramfunc))¶

Calculate the CRC for the given data.

Calculate the n-bit CRC of a message buffer by using a lookup table to get the CRC of each byte. The CRC lookup table should be initialized by calling PM_tformat_generateCRCTable() before this function.

Attention

  • This CRC assumes that the number of data bits is always divisible by 8. This is true for T-format data.

This function can be used for both transmit CRC calculations (EEPROM read/write commands) and verification of the received CRC.

See

PM_tformat_generateCRCTable

See

This function is called by the specific tformat_getCRCIDx functions:

  • tformat_getCRCID0_1_7_8_C

  • tformat_getCRCID2

  • tformat_getCRCID3

  • tformat_getCRCID6

  • tformat_getCRCIDD

Parameters

  • nBitsData – number of bits of data for which the CRC is calculated

  • msg – pointer to the data on which the CRC will be calculated

  • crcTable – pointer to the table where the CRC values are stored

  • rxLen – number of bytes of data for the CRC calculation
