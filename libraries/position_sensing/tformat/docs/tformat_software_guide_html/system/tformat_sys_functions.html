3. System-Level Functions¶

This section describes functions which act at the system-level. This includes initialization of the C2000 device, start-up functions and interrupt service routine.

Many of these functions make calls to the T-Format Library which is described in the T-Format Library Documentation.

3.1. System Initialization Functions¶

The following functions are called to initialize the example system.

void tformat_init(void)¶

Initialize the T-Format subsystem.

void tformat_initSPIFIFO(uint32_t devLSPCLKFreq)¶

Configure the SPI peripheral.

Configures the PM_TFORMAT_SPI peripheral as required for T-Format communication

Parameters

  • devLSPCLKFreq – SPI clock rate

Returns

None.

3.2. System Run-time Functions¶

The following functions are called during run-time. They perform application specific functions make calls into the solution library.

void tformat_exCommands(void) __attribute__((ramfunc)) __attribute__((noreturn))¶

Execute read-out and reset commands.

This function is the main test for the system example. It tests the following command IDs: ID0, ID1, ID2, ID3, ID7, ID8 and IDC

For each command ID:

  1. Clear the tformatData structure (optional) Not required, but useful for debug.

  2. Wait…The idle time between commands is for demo purposes. The idle time is not tied to any specification

  3. Setup the SPI and CLB for the command

  4. Start the operation

  5. Wait for the dataReady flag to be set by the SPI RX ISR.

  6. Unpack the data from the SPI FIFO into the tformatData structure

  7. Check for errors using tformat_checkError();

  8. Update the turns, position, and ID when appropriate by calling the PM_tformat_updatePositionOrTurns() and PM_tformat_updateEncoderID() library functions.

This function runs in a infinite while() loop.

See

The EEPROM read and write commands are tested in the function tformat_testEEPROMCommands()

Returns

None.

void tformat_testEEPROMCommands(void) __attribute__((ramfunc))¶

Execute EEPROM read and write commands.

Test read (ID6) and write (IDD) EEPROM commands.

  1. Write all 0’s to EEPROM address in the range defined by TFORMAT_EEPROM_TEST_ADDR_START and TFORMAT_EEPROM_TEST_ADDR_END.

  2. Read out the data and check that all data read is 0x0

  3. Write a decrementing pattern: 0xFF, 0xFE, 0xFD … to the EEPROM address range

  4. Read out the pattern and check that the data matches what was written.

After each read or write:

Check the response from the encoder against the command. The controlField (CF), eepromAddressField (ADF) and eepromDataField (EDF) received from the encoder should match the command that was sent.

Note: Some write attempts will occur when the EEPROM is busy. In this case the PM_TFORMAT_EEPROM_BUSY flag will be set and the write will be re-tried by the test.

All of the other commands are tested in the tformat_exCommands() function.

Returns

None.

uint16_t tformat_checkError(uint16_t controlFieldID) __attribute__((ramfunc))¶

Basic error check for received fields.

Provides basic checks of the following:

  1. The received control field (CF) should match the request CF

  2. The calculated CRC for the data should match the received CRC field

  3. For EEPROM read and write commands, check the request address and data fields against the received fields.

Parameters

  • controlFieldID – The control field (CF) of the request in the format PM_TFORMAT_CFIDx. For example PM_TFORMAT_CFID6 for command ID6.

void tformat_spiRxISR(void) __attribute__((interrupt("HPI"))) __attribute__((ramfunc))¶

Service the SPI FIFO receive interrupt.

This interrupt service routine will move the contents of the SPI RX FIFO into the tformatRxData array. Each FIFO word is masked with 0xFF to extract only the 8-bits of data corresponding to the for the specific T-Format field.

Note

This interrupt service routine is defined as a high-priority interrupt for performance reasons. This means the ISR can not be interrupted by another ISR (no nesting allowed). Refer to the C2000 compiler guide for more information.
